# Weekly publication protocol

The user authorized weekly research and stock-analysis reports, committed and pushed to this repository, and on October 17 extended this to conditional portfolio projections and visual editions on the existing wiki. Run the workflows sequentially in one Saturday 9 AM America/Chicago automation. Use the client timezone for report dates. Run setup work separately from recurring publication.

## Isolated run

1. Resolve the source checkout and its Git common directory. Acquire a directory lock named `investing-weekly.lock` in that common directory. Record the run ID, owner and start time in the lock. Release only this run's lock on every exit, including source, commit and push failures; preserve failed report work for recovery. If occupied, do not run a second publisher. Do not delete an unknown lock; report a stale-lock problem when a run has demonstrably ended.
2. Verify origin is the intended `ChrisWiles/wiles-wiki` repository and the default branch is still `main`; check visibility. Fetch origin/main. Before new generation, inspect retained-run manifests under `<git-common-dir>/investing-unpublished/`. Validate each manifest's repository, run/worktree ownership, expected output paths and retained commit. Check whether the commit already reached origin/main; if so, reconcile state and retire only that completed run. Otherwise recover its authored reports, research frontiers, queue and journal IDs into the current remote-based worktree (or rebase its owned worktree) and review conflicts before continuing. Preserve the original proposal/evidence, use its existing D-ID, and retain its original report date. Never blindly overwrite newer remote decisions or import paths outside the recurring allowlist. An unresolved recovery conflict stops publication while preserving both versions. Create a temporary detached Git worktree from the fetched commit when no owned recovery worktree is reused. Run public research and write reports there. Never reset, stash, switch branches or stage unrelated changes in the source checkout.
3. Read committed holdings in the report worktree and compare with newer source-checkout holdings when available. Use the newer user-provided quantities for analysis without automatically altering the holdings references. Household positions and allocations are authorized for public reports. If quantities are unavailable, label the affected calculations incomplete; do not infer them.
   For tax-aware review, also read the confirmed `investing/tax-context.md` and available user-provided local inputs under the source checkout's ignored `private/investing/inputs/`. Copy only necessary inputs into this run's ignored scratch area if needed; retain their as-of dates and provenance. Detached worktrees do not inherit ignored files. Absent inputs remain explicit gaps; never stage raw broker documents, personal income/tax-profile details or account identifiers. Original user files stay intact.
4. Load the new worktree's mandate, prior committed state and latest reports. Use `research-prioritization` to select deeper work, run `ai-research-monitor` then `stock-analysis`, rerank the queue and run `decision-journal` for material decisions/due reviews. Finalize both reports against `investing/report-contract.md`. If research refresh fails, stock analysis may proceed from the last verified state with its age disclosed. A source failure must not become a new factual finding.

On any failure after report/journal work exists, save a small retained-run manifest in the Git common directory before releasing the lock: repository identity, run ID, owned worktree path, report date, status, retained commit (if created), exact output paths and authored D-IDs. This local recovery metadata is not a public report. Failed work is not abandoned merely because the next run has a new date. If recovery cannot be made safe, report the blocker without regenerating duplicate decisions.

## Report boundaries

Allowed recurring writes:
- `reports/investing/research/YYYY-MM-DD.md`
- `reports/investing/stocks/YYYY-MM-DD.md`
- `reports/investing/projections/YYYY-MM-DD.md`
- `investing/models/inputs/YYYY-MM-DD.json` or a same-date correction `YYYY-MM-DD-vN.json` containing reviewed identifier-free prices/derived returns and positions
- `investing/forecasts/P-YYYY-MM-DD-vN.json` containing immutable conditional results/diagnostics
- `investing/models/agi-inputs/YYYY-MM-DD-vN.json` containing reviewed identifier-free AGI economic assumptions, source dates and judgment-weight rationale
- `investing/forecasts/A-YYYY-MM-DD-vN.json` containing immutable AGI scenario endpoints, weights and exact P-ID/holdings/input lineage
- `reports/investing/index.md`
- `investing/state/research.md`
- `investing/state/companies.md`
- `investing/state/portfolio.md`
- `investing/research-queue.md`
- `investing/decisions/index.md`
- `investing/decisions/D-YYYY-MM-DD-NNN.md`

Do not stage skills, model/renderer source, holdings, raw broker/market downloads, private output, secrets, generated caches or unrelated wiki files during a weekly run. Generated `public/` HTML is never staged. The reviewed public input/result files above are distinct from raw private documents. The report date is the local run date; a same-date rerun revises that report rather than creating duplicate entries. Use per-source verified-through frontiers and unresolved retry items to set lookback windows; a partial report does not advance unverified coverage. Include missed weeks and corrected older findings. A quiet week still produces concise dated reports saying which sources were checked and what remains unchanged.

## Verification and push

- Check every numerical claim against its cited source, units, date, period, accounting basis and scenario assumptions. Material valuation calculations require exact arithmetic and an independent input check. Do not promote a report to complete if required coverage was skipped; disclose partial coverage prominently.
- Audit the entire public diff for credentials, unrelated private documents, fabricated account/market data, unsupported trade levels and mistaken ticker identities. Household investment positions and allocations are authorized content. Review all staged paths. Run `git diff --check` and relevant skill/tool validations.
- Before committing, apply the maintained `finance-report-design` [weekly quality standard](../.skills/finance-report-design/references/weekly-quality.md): build the shared design, pass its browser checker for the requested date, then inspect desktop/phone screenshots and the report opening. Keep QA evidence ignored and record the actual review result in supporting detail. Failed or unperformed required visual checks retain the draft for recovery and surface a meaningful failure; they do not become a claim of completed publication. Independent research may continue.
- Stage only the exact report, state, queue and journal files generated in this run. Verify that journal execution claims have user/transaction confirmation and that prior reasoning was preserved. Inspect the staged diff. If there is a substantive change, commit with `reports(investing): weekly research and stock review YYYY-MM-DD`. An identical same-date rerun is a no-op.
- Push `HEAD:refs/heads/main` without force. If the remote advanced, fetch and rebase the isolated report commit onto origin/main once. Reread any newly landed research, company/portfolio state, queue, journal and reports, then regenerate affected comparisons, preserve unresolved source retries and reconcile the report index even if Git found no textual conflict. If report/state conflicts require changes, resolve from both versions, rerun checks, then push once more. Stop on continued rejection, permission failure or unresolved conflict and retain the report commit for recovery. Never report success without a successful push and verification that origin/main contains the commit.
- After success, a clean report-path source checkout on main may fast-forward to origin/main without touching unrelated dirty files. If fast-forward is unsafe or fails, keep the source checkout intact and provide the GitHub report links. Remove only this run's clean temporary worktree and release its lock; retain recoverable failed work.
- Apply `investing/web-publication.md`: verify the Pages deployment contains the published commit, rerun the same browser checker against the live archive for that report date and verify its forecast matches canonical JSON. If deployment or live verification fails, distinguish the successful report push from incomplete web verification, retain recovery evidence and notify the meaningful failure. Do not edit site/model/skill source automatically.
- Notify once after a successful weekly report, or when a meaningful failure requires action. No interim unchanged polling notices. Cite report links and commit SHA; distinguish analysis completion from publication completion.

For the AGI layer, review `investing/models/agi-scenarios.md` and prior assumptions. Publish a new A vintage only for a reviewed input/assumption change; otherwise explicitly carry the prior date. Preserve old A/P inputs/results and target dates. Verify judgment weights, six-horizon economic bridge arithmetic, issuer/fund accounting and price-only scope independently of the market model. A partial source review cannot silently refresh all parameter dates or present analyst weights as Anthropic/validated probabilities. Required local/live visual checks include the AGI section. Recurring runs may write only the newly allowed A inputs/results; code, skills and holdings remain outside their write scope.
